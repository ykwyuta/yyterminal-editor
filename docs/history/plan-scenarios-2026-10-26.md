# 2026-10-26 実行計画の接続修正と15シナリオの7DB検証

対象はv0.7.1からの作業ツリー。共有YYクレートは`a5c7fa2a43ec6ff531426610133688ff3875d3ff`のまま。共有ソースを複製・変更せず、エディタの表示アダプターで補正した。

## 原因と修正

SQLiteの2表結合は、EQPのSCAN/SEARCHが同じparent=0で返ることがある。共有パーサーでは両方が親なしとなり、画面がそれぞれを別のQueryとして描画していた。同じSQLのルートを`SQLite query (display group)`へ接続し、既存のDB由来の辺と原文を保持する。表示用親には`Display.Synthetic=true`を付け、DBが報告したJOINや実測演算子と区別した。元の2アクセスは表示用親を含む3カード・2辺で表示する。

追加検証ではMySQLの相関スカラー副問い合わせにも問題があった。推定JSONのselect_list_subqueriesが共有パーサーの対象外で、SELECT句のサブクエリが表示されなかった。このコンテナを対応済みのattached_subqueriesへ変換して共有パーサーで再解析し、元のJSONを保持する。既存のattached_subqueries、入れ子のサブクエリも保持する。MySQL実測TREEの複数ルートも同じSQLなら表示用親へ接続する。今回の相関スカラー副問い合わせは推定が2→4カード、実測が4→5カードになった。

ライブ取得と計画ファイル読込に同じ補正を適用し、再適用でノードが増えないことを検証した。異なるQuery.Textは別グループを維持する。表示用親に推定行数・実測行数・コストは追加しない。

## 15シナリオ

SQL一覧は`demo/database/plan-scenarios.json`。単表走査、主キー検索、2表結合、自己LEFT JOIN、3表結合、5表集約、HAVING/ソート、DISTINCT結合、相関EXISTS、相関NOT EXISTS、IN副問い合わせ、相関スカラー副問い合わせ、集約派生表LEFT JOIN、CTE/ROW_NUMBER、UNION ALLを実行した。

## 通常検査

- Linux x64：fmt、全ターゲットClippy（警告禁止）、通常116試験が成功。実PTY16試験を含み、SQLite2表結合の表示用親・接続矢印・画面縮小・保存と終了を確認した。
- Windows x64：全ターゲットClippyと単体試験を検証。起動中のyyte.exeは上書きできないため、Linuxで全結合試験を実行した。
- SQLite/MySQL補正の単体試験では原文・既存辺・計測値・Query.Text境界・再適用の安定性を確認。MySQLの既存attached_subqueriesと入れ子のselect_list_subqueriesも検証した。

データやオプティマイザーの違いを網羅するものではなく、今回の15パターンと既存デモに対する結果である。

公開バージョンはv0.7.2（Cargoパッケージ0.7.2）。4環境のCIで検証した当該コミットの資材を配布する。

リリースCIでは既存のDB計画PTY試験に操作完了待ちの競合が出た。前の演算子にも存在するCost表示では次演算子への移動完了を判断できなかったため、対象演算子のプロパティ表示（表示対象: Sort）とメニュー終了を待ってからリサイズするよう修正した。固定sleepは追加しない。

接続確認の既存単体試験も、初期フォルダー読込がステータス文字列を更新する競合があったため、接続先とキャンセルハンドルの保持を検証するよう修正した。DBワーカーの期限付き完了待ちは維持した。
