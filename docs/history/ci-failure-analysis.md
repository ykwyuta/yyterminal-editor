# CI失敗分析

## 2026-10-25: CUIのターミナルからエディタへ戻った後の終了待ち

実行: [CI 40167334116 / Ubuntu](https://github.com/ykwyuta/yyterminal-editor/actions/runs/40167334116/job/121090960002)。対象SHAは `4c8493169cfe1c55780188696a3170d8b2756ec7`。`cargo test --workspace --locked` の `interactive_editor_save_preview_shell_resize_and_exit` が終了待ちで失敗した。ユニット試験と、構文色・言語変更・プレビュー色の新しい実端末試験は成功し、Windowsジョブはfail-fastでキャンセルされた。

確認済みの問題: 試験はF2送信後にファイル名が画面に現れることだけを待っていた。ファイル名はターミナル表示中も共通タブに常時表示されるため、エディタへの切り替え完了を証明しない。また、この試験だけが独自の端末待機ループを持ち、一部の待機では端末照会への応答も共通ハーネスと異なっていた。終了入力が実際にどう処理されたかは失敗ログにないため、CIでの入力タイミングとの因果関係は推定として扱う。

対応: 共通のHarnessを利用し、プレビュー完了、実際のTerminal表示、入力エコーでは一致しないシェルの完了マーカー、サイズ変更後の枠、Editorの見出し・文書内容・未変更タブの表示が揃う状態を順番に待つ。終了はその後に1回だけ送る。待ち時間の延長、試験の再実行による成功扱い、エラーの無視は行わない。失敗時は共通ハーネスで実際の画面を出力し、自分のプロセスとパイプを回収する。

再発防止: タブ名など複数の表示モードに共通する文字列を、ビュー切り替え完了の単独条件にしない。実際のビュー見出しと操作結果の内容を組み合わせ、共通の端末応答・状態待機を利用する。修正後の検証結果は以下へ追記する。

ローカル検証: 修正後のWindowsでfmt・Clippy・66試験、Linuxコンテナでfmt・Clippy・80試験（対象のサイズ変更・終了試験を含む）が成功した。GitHub CIについては修正コミットの完了結果を確認してリリースする。
