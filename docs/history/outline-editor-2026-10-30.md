# アウトライン編集の実装・検証（2026-10-30）

yyeditor `c5defe2ba36f9113201c2bf5709b5a82bf4c32ec` のアウトライン仕様を確認し、同じ `yyoutline` version 1 JSONを編集するCUIを追加した。共有YYクレートの参照SHAは変更せず、WebView向けJavaScriptや文字コード表を複製していない。

`.yyoutline` の自動表示、通常JSONからの手動切り替え、項目の文章編集、枝の追加・削除・階層変更・上下移動、折りたたみ、ズーム、ブックマーク、参照・参照元、点・番号表示、HTTP(S) URLの起動、Markdown出力、原文編集との往復を実装した。IDと追加フィールドを保持し、保存は既存Document・Undo/Redo・外部変更検査の経路を使用する。

検証結果：

- Windows x86_64、Rust 1.99.0でfmt、全ターゲットClippy、通常112試験、配布ツール5試験が成功。
- manylinux_2_28 x86_64でLinuxの全ターゲットClippyが成功。通常133試験と配布ツール5試験も成功。実PTY19試験のうち、新しいアウトライン試験で日本語編集、枝移動、参照追加、保存・再読込、Undo/Redo、Markdown出力、原文表示を確認。
- アウトラインのモデル・統合試験8件で、不正JSON、重複ID・階層、未知フィールド、3,000階層、削除後の参照、読み取り専用、上限超過の原子性、CRLFでのサイズ上限と不要な履歴の防止、入力中に文書・項目が変わった場合の拒否、狭い画面と大量参照の表示を確認。
- Rustが出力したJSONをyyeditorの実際の `outline-model.js` で読み、枝移動と再保存を実行。再保存したJSONをRustで読み直し、JSONの値とMarkdown出力の完全一致を確認した。番号付き・深い階層・日本語・Markdown記号を含む文章も対象にした。
- yyeditor同梱の `demo/outline/example.yyoutline` も同じ手順で読み戻し、JSONとMarkdownの一致を確認。

Linuxの初回並列試験では、変更していないDBエクスポート試験がチャネル待ちで時間切れになった。ビルド済み環境で逐次試験、続いて通常の並列試験を再実行し、どちらも全件成功した。DB試験のタイムアウトを緩めたり、試験を除外したりする変更は行っていない。外部の実DB試験と手動ベンチマークは従来どおり通常試験ではignoredである。

操作は [利用説明](../user/outline.md)、構成・形式は [内部仕様](../developer/outline.md) を参照。
