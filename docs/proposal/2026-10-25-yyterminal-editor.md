# yyterminal-editor 企画案

- 作成日: 2026-10-25
- 状態: 企画・設計案。実装済み機能の一覧ではない。
- 対象リポジトリ: https://github.com/ykwyuta/yyterminal-editor
- アプリケーション名: yyterminal-editor（仮称）
- 実行コマンド案: `yyte`
- 既存資産の調査基準: yyeditor `a5c7fa2a43ec6ff531426610133688ff3875d3ff`

## 1. 目的

Linuxのターミナル内で、エクスプローラー、タブ付きエディタ、統合ターミナル、Git操作画面、Markdownプレビューを一体で利用できる開発・データ保守ツールを作る。位置付けはYYシリーズのLinux CUI版である。

編集操作はVS Codeに近い、メニュー・コマンドパレット・通常のショートカットを中心とする。起動直後から文字を入力でき、vimのノーマル／挿入モードやEmacsの操作体系を習得する必要がない。

汎用的なソース編集に加え、YYシリーズが持つ巨大ファイル、日本語・ホスト文字コード、COBOL固定長、CSV・TSV、独自ファイル形式を扱う能力を製品の柱にする。Windows版とLinux版の間で、同じデータとレイアウトを持ち運べることを重視する。

### 合意した要件

| 分野 | 必須要件 |
| --- | --- |
| 実行形態 | Linuxのターミナル内で動くCUI。デスクトップ環境やWebViewを必須にしない |
| 画面 | エクスプローラー、エディタ、統合ターミナル、Git、Markdownプレビュー |
| 操作 | VS Codeに近い非モーダル編集。キー操作とメニューから主要機能へ到達できる |
| 大規模データ | ファイル全体のメモリ展開を前提としない閲覧・検索・編集・保存 |
| 文字コード | yyeditorと同じ共有コーデックを使い、EBCDIC系や独自対応表を扱う |
| データ編集 | 固定長のレコード／項目編集、CSV・TSVなどの表形式編集 |
| 互換性 | 既存YY形式を共通ライブラリで解釈し、互換性の範囲を形式ごとに明示する |
| フォント | **同梱しない。特定フォントの導入も必須にしない**。端末側のフォントを利用する |

## 2. 対象利用者と利用場面

- SSHでLinuxサーバーへ接続し、設定・ソース・ログを同じ画面で扱う人。
- GUIを導入できないサーバーやコンテナで、ファイル操作とGit操作を行う人。
- メインフレーム由来のEBCDIC、COBOL固定長、巨大なCSVを調査・修正する人。
- WindowsのYYシリーズで作ったレイアウトや作業ファイルをLinuxでも利用したい人。

代表的な操作は次の流れとする。

1. `yyte /work/project`でフォルダーを開く。
2. 左のツリーからソースやデータを開き、通常のキー操作で編集する。
3. 下部のターミナルでビルド・テスト・シェル操作を行う。
4. Git画面で差分を確認してステージし、コミットする。
5. Markdownを左右に分割して編集・確認する。
6. 固定長ファイルに`.yyl`を適用し、項目単位で値を確認・修正する。

SSH先で実行した場合、ファイル、Git、統合シェルはそのSSH先で動く。接続元へのデータ転送は、この通常操作の必須条件にしない。

## 3. 製品範囲と完成条件

初版の完成条件には、基本IDE画面だけでなく、ホスト文字コード・固定長・CSV編集と対象YY形式の往復互換も含める。基本エディタだけの段階は技術プレビューと位置付ける。

### 初版で完成させる範囲

- 複数フォルダーのワークスペース、ツリー、タブ、画面分割、コマンドパレット。
- 通常テキスト、巨大ファイル、長大行、文字コード指定、検索・置換、Undo／Redo、安全な保存。
- CSV・TSV・任意区切りの表編集と原文表示。
- COBOLコピーブック、単一／マルチレイアウトの固定長編集。
- PTYで動く複数の統合ターミナル。
- Gitの状態・差分・ステージ・コミット・ブランチ・fetch／pull／push。
- Markdownのターミナル内プレビュー。
- `.yyworkspace`、`.yyl`、`.yys`など、後述の優先形式の読み書きと互換性試験。
- オフラインで読めるヘルプと、端末能力に応じた代替操作。

### 段階的に拡張する範囲

LSP補完・診断、DAPデバッグ、GUI並みの画像付きMarkdown、Mermaid／LaTeXの画像化、YYの図・3D・ER・実行計画の専用ビュー、アプリ内部からのSSH接続は後続段階とする。VS Code拡張機能の実行互換やMarketplace互換は初版要件に含めない。

## 4. 画面と操作体験

### 4.1 標準画面

```text
┌ ファイル  編集  選択  表示  移動  実行  Git  ヘルプ ──────────────┐
│ EXPLORER        │ orders.cbl  orders.csv  README.md *             │
│ project/        ├──────────────────────┬─────────────────────────┤
│  src/           │ エディタ             │ Markdownプレビュー      │
│   orders.cbl    │ 行番号・選択・検索   │ 見出し・表・コード      │
│  data/          │                      │                         │
│   orders.csv    ├──────────────────────┴─────────────────────────┤
│  README.md      │ TERMINAL 1 / TERMINAL 2 / 問題 / 出力            │
│                 │ $ cargo test                                   │
├─────────────────┴────────────────────────────────────────────────┤
│ main  変更3件  UTF-8  LF  Ln 12, Col 4  編集  検索中  メモリ使用量│
└──────────────────────────────────────────────────────────────────┘
```

左サイドバーをエクスプローラー・検索・Gitで切り替え、中央は文書ごとのタブ、下部は端末・処理出力にする。Gitの差分やCSV／固定長の表も中央のタブとして開く。

80×24でも主要操作ができるようにする。狭い画面ではサイドバーと下部パネルを畳み、分割表示は一方ずつ切り替える。初期配置の推奨は120×36以上とするが、画面サイズを動作条件にしない。リサイズ後も選択位置・編集中セル・PTYサイズを保つ。

### 4.2 キーバインド案

以下はアプリにそのキーが届く場合の既定案である。親端末が先に消費するキー、端末プロトコル上区別できないキーについて、同一動作を保証しない。

| 操作 | 主なキー案 | 代替経路 |
| --- | --- | --- |
| コマンドパレット | Ctrl+Shift+P | F1 |
| ファイルのクイックオープン | Ctrl+P | パレット／ファイルメニュー |
| 保存 | Ctrl+S | パレット／ファイルメニュー |
| 名前を付けて保存 | Ctrl+Shift+S | ファイルメニュー |
| 検索／置換 | Ctrl+F／Ctrl+H | 編集メニュー |
| フォルダー横断検索 | Ctrl+Shift+F | 検索サイドバー |
| Undo／Redo | Ctrl+Z／Ctrl+Y | 編集メニュー |
| 選択・コピー・切り取り・貼り付け | Shift+矢印、Ctrl+C／X／V | メニュー／端末側クリップボード |
| 次／前の文書 | Ctrl+Tab／Ctrl+Shift+Tab | タブ一覧／パレット |
| サイドバーの表示切替 | Ctrl+B | 表示メニュー |
| 統合ターミナルの表示切替 | Ctrl+` | 表示メニュー |
| 次のペインへフォーカス移動 | F6 | フォーカス先一覧 |
| メニューを開く | F10 | パレット |
| タブを閉じる | Ctrl+W | タブメニュー。未保存は確認 |
| アプリ終了 | Ctrl+Q | ファイルメニュー。未保存・子プロセスを確認 |

カーソル・Home／End・PageUp／PageDown、Shift選択、マウスによる選択・ツリー展開・ペインサイズ変更を用意する。複数カーソルと矩形選択は、内部モデルと表示座標を分離したうえで段階導入する。

全操作をコマンドIDで登録し、メニュー・パレット・キー設定から同じ処理を呼ぶ。通常の編集でEscを押しても、vimのノーマルモードのような状態には移らない。

### 4.3 端末特有のキー制約

従来の端末入力ではCtrl+IとTab、Ctrl+MとEnterなどが同じバイト列になり、Ctrl+Shiftの組合せも識別できないことがある。拡張キー報告を検出し、利用可能な場合に有効化する。kitty keyboard protocolは候補の一つであり、全端末・全tmux／screen経路での利用を前提にしない。[kittyの公式仕様](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)を実装判断の参照とする。

rawモードとフロー制御の扱いを明示し、Ctrl+Sによって画面出力が止まらないようにする。終了・例外・中断時は端末設定、キー報告、マウス追跡、カーソル表示を復元する。

`yyte --check-terminal`を設け、色・キー・貼り付け・マウス・文字幅・クリップボード能力を診断する。届かないショートカットの再設定方法と代替操作を表示する。

### 4.4 フォーカスと統合ターミナル

エディタと子シェルの入力を分ける。子シェルにフォーカスがある場合、Ctrl+CはSIGINTに相当する入力、Ctrl+Zはシェル側のジョブ制御へ送る。エディタではそれぞれコピーとUndoとする。フォーカス先は枠・見出し・ステータスで明示する。

アプリ共通操作の予約キーは少数に限定し、対応するシーケンスを識別できる場合だけ先に処理する。「次のペイン」「フォーカス解除」の経路を必ず残す。端末へのキー送出は、親から受けたバイト列の単純転送ではなく、子端末のモードを見て符号化する。

## 5. 機能企画

### 5.1 エクスプローラーとワークスペース

複数ルート、遅延展開、隠しファイル、`.gitignore`を考慮した表示、絞り込み、作成・名前変更・移動・コピー・削除を提供する。削除は対象と件数を確認し、利用可能な場合はごみ箱を選べる。シンボリックリンクは循環を検出し、ルート外の操作を分かるように表示する。

大きなディレクトリの全走査をUIスレッドで行わない。ファイル名がUTF-8でない場合もLinuxの生バイト名を内部で保持し、表示用文字列から元のパスを再構築しない。

ワークスペースは既存の`.yyworkspace`を読み書きする。Windowsドライブ・UNC・Linux絶対パスの差は明示的なパスマッピングで解決し、別OSのパスを勝手に作り替えて保存しない。

### 5.2 テキストエディタ

タブ、左右／上下分割、行番号、シンタックス色、インデント、改行指定、文字コードの指定・開き直し、検索・置換、ファイル横断検索、ジャンプ、Undo／Redo、自動回復を提供する。

表示座標、Unicodeの文字境界、元ファイルのバイト位置を別々に管理する。日本語の全角、結合文字、タブ、絵文字、不可視文字を含む選択・横スクロール・矩形選択を検証する。入力自体のIMEは親端末が担い、受け取った確定文字列とbracketed pasteを適切に扱う。

他プロセスの更新を検出したら再読込・差分確認・別名保存を提示する。元ファイルの削除や置換、ログローテーションを「同じパスだから同じ内容」とみなさない。

### 5.3 巨大ファイル

既存のピースツリー・部分デコード・表示範囲計算を流用し、初回表示のために全ファイルをUnicode文字列へ変換しない。行番号索引・検索・構文解析・集計はバックグラウンドで段階的に進め、未確定の結果を確定値として表示しない。

1行が数GBのファイル、改行のないファイル、巨大なフィールドを持つCSVも、表示範囲を分割して扱う。全件検索・全置換・ソートは明示的なジョブとし、進捗・中止・一時ディスク使用量を示す。

メモリ・ワーカー数・一時領域に上限を設ける。候補オプションは`--memory-limit`、`--jobs`、`--temp-dir`。索引・Undo・PTYスクロールバック・プレビューの予算を別々に計上し、合計を管理する。

**Linuxのmmap安全性は移植前の必須検証項目にする。** yy-ioの既存ファイルオープンはWindowsでは書き込み共有を制限するが、その仕組みをLinuxの排他保証として扱えない。外部更新可能なファイルは、範囲読み出しキャッシュ、整合性を確認した一時スナップショット、または利用条件を満たす安定ソースとして扱う。外部truncateによりUIプロセスを落とす設計は採用しない。

保存は同一ディレクトリの一時ファイルへ出力し、競合検査・同期・置換を行う。中止時の元ファイル保持、パーミッション、ACL、拡張属性、ハードリンク／シンボリックリンクの扱いを仕様化する。対応しない属性を黙って失わせない。

### 5.4 ホスト文字コード

`YYLibrary`の`yy-encoding`を同じコミットで利用し、独自の変換表をCUI側に複製しない。対象は既存yyeditorに合わせ、UTF系列、CP932／Shift_JIS、JIS X 0213系、EUC-JP、ISO-2022-JP、EBCDIC IBM-930／939／1390／1399／290／1027／037／500／1047などとする。最終的な一覧は共有コーデックが実際に提供するものから生成する。

EBCDICではNL・LF・固定長の区切り、SO／SI、レコード境界での状態復帰を区別する。不正バイト・未知の外字・制御バイトがあるファイルを開けなくしない。元のバイトと表示文字を対応付け、未編集領域はバイトを保持する。

文字コード変換、桁あふれ、表現できない文字の置換は、件数と位置を示して保存前に確認する。生バイトを保持する編集と、指定文字コードへの変換保存を別のコマンドにする。

### 5.5 固定長ファイル編集

レコード長・改行区切り・文字コード・数値のエンディアンを指定し、レコード一覧、項目表、原文／16進表示を切り替える。レイアウトは既存の`.yyl`とCOBOLコピーブックを利用する。

`PIC X／N／G／9`、符号付きゾーン十進、`COMP-3`、`COMP／BINARY／COMP-5`等を共有COBOLコーデックで扱う。数値は浮動小数点に一律変換せず、精度と元バイトを保持する。壊れたパック十進数は値と原バイトの両方を確認でき、未編集ならそのまま保存する。

単一レイアウトだけでなく、レコード識別条件、優先順位、手動割当、未分類レコードを持つマルチレイアウトに対応する。項目・レコード長推定は候補として提示し、人が採否・修正を行えるようにする。推定結果を無確認で保存仕様にしない。

表形式のセル編集・矩形選択・TSVコピー＆ペーストを提供する。項目幅の超過、DBCSの途中切断、レコード長を崩す変更は書込み前に検出する。原文・表・16進表示は同一の文書状態を共有し、各画面の変更が別コピーにならないようにする。

### 5.6 CSV・TSV編集

RFC 4180を基準とした引用符・二重引用符・フィールド内改行を扱う。TSV・任意区切りは別の明示設定とし、ヘッダー・文字コード・改行・区切りを検出または手動指定できるようにする。

行・列の仮想表示、セル編集、範囲選択、コピー＆ペースト、行列の追加・削除、フィルター、並べ替え、列の固定を提供する。先頭ゼロ、大きな整数、日付のように見える文字列を勝手に数値へ変えない。

「原文を編集」「表として編集」「変換してエクスポート」を区別する。未編集の原文保存ではバイト一致を保証する。構造変更時の引用符・区切り・改行の再生成方針を示し、書式の正規化が必要なら明示する。巨大CSVの全件ソート・型推定・集計は外部処理可能なジョブとする。

`.yys`を開く場合は数式、複数シート、書式、固定長レイアウトなどのデータを保持する。初版UIで編集できない属性は明示し、保存で失わないことを互換性条件にする。

### 5.7 統合ターミナル

Linux PTY上に利用者のシェルを起動し、端末タブ、作業ディレクトリ、履歴表示、選択・コピー、検索を提供する。既存`yy-term`のVT解釈・画面モデル・キー符号化を再利用し、PTY起動とCUI描画のアダプターを新設する。

`SIGWINCH`、ウィンドウサイズ、子の終了コード、ジョブ制御、プロセスグループを扱う。端末タブを閉じる操作とアプリ終了時の子プロセス処理を明示する。tmux／screenで維持するセッションは、通常の子シェル終了と区別してデタッチする。

子プロセスの出力をそのまま親端末へ書かず、端末モデルへ解釈してからセルとして描く。子が送る画面消去・OSC・タイトル変更・クリップボード操作を、親端末の操作として無条件に実行しない。履歴と出力量は上限を持ち、コマンド実行中もエディタの入力を止めない。

### 5.8 Git操作画面

ワークツリー／index／HEADを区別した変更一覧、差分、ステージ／解除、コミット、ブランチ、fetch／pull／push、履歴、競合一覧を用意する。巨大差分は範囲ごとに表示し、バイナリ・文字コード不明・追跡外ファイルを区別する。

既存`yy-git`の処理と外部Gitコマンドを流用候補にする。`git status --porcelain`等の機械向け出力とNUL区切りを使い、パスをシェル文字列へ連結しない。Gitが要求する認証や対話は、秘密情報をログへ記録せずに提示する。

破棄・reset・強制pushなどは通常のstage／commitと別の確認を持たせる。GUI版yymergeの起動を必須にせず、基本差分はCUI内に表示する。yymergeのLinux CLIは高度な比較・3方向マージの連携候補とし、利用可能な機能を別途確認する。

### 5.9 Markdownプレビュー

初版はブラウザーなしで、見出し、段落、強調、箇条書き、チェックリスト、表、コード、引用、リンクを端末セルに整形表示する。編集とプレビューを分割し、ソース位置との対応を保持する。大きな文書は表示範囲と更新箇所を中心に再描画する。

既存`yy-preview`からパーサー・文書変換に使える部分を流用するが、HTML出力やWebView2向けテンプレートはCUI描画としてそのまま使えない。端末用のMarkdownレンダラーを設ける。

画像、Mermaid、LaTeXは通常の端末では説明・リンク・コード等で表示する。後続段階で、能力検出した端末の画像プロトコルに対応する。画像表示非対応のSSH／tmux経路でも本文の閲覧を可能にする。外部ブラウザーは任意の補助手段とし、プレビュー必須条件にしない。

Markdown内のHTML・スクリプト・外部画像を自動実行・自動取得しない。セル幅超過、制御シーケンス、異常に長いリンクやコードブロックも描画上限で処理する。

## 6. フォント・文字幅・表示能力

**フォントファイルは配布物にもリポジトリにも同梱しない。フォントの自動インストールや変更も行わない。** 親端末が選択したフォントで表示し、UDEV GothicやNerd Fontsを導入していなくても操作できることを要件とする。

アプリアイコンは端末内では文字ラベルを基本とし、特殊グリフだけで機能を識別させない。Unicode罫線が崩れる環境にはASCII罫線を用意する。色数もtrue color・256色・基本色へ段階的に落とせるようにする。

全角・結合文字・East Asian Ambiguous・絵文字の幅は端末との不一致があり得る。能力情報と利用者設定で幅ポリシーを選び、診断画面で試験文字列を表示する。外側の端末に描画するセル幅と、ファイル上のバイト幅・固定長項目幅を混同しない。

SSH先のアプリが接続元PCのフォントを切り替える仕様は持たない。フォント設定を親端末が持つ例は[Ghosttyの公式設定](https://ghostty.org/docs/config/reference#font-family)でも確認できるが、特定の端末ソフトを必須にはしない。

## 7. YY形式の互換性

「互換」を拡張子が開けることだけで判定しない。読込み、意味の保持、未対応属性の保持、再保存、Windows版での再読込みを試験する。現在の形式バージョンと互換範囲をマニフェストに記録する。

| 形式・資材 | 初版の方針 | 互換性の条件 |
| --- | --- | --- |
| 通常テキスト・ホスト文字コードファイル | 読み書き・編集 | 未編集は原バイト保持。変換保存は明示操作 |
| `.yyworkspace`（TOML） | 読み書き | 複数ルート・相対パスを維持。OS間のパス差を明示 |
| `.yyl`（TOML）・COBOLコピーブック | 読込み・レイアウト編集・保存 | 単一／マルチレイアウト、文字コード、レコード条件を保持 |
| `.yys`（YYSHEET形式） | 読み書き・表編集 | 既存の共有シリアライザーを利用。式・書式・レイアウト等を欠落させない |
| 共有文字コード対応表 | 読込み・利用 | YYLibraryの形式・優先順位に合わせる |
| `connections.toml`・`known_hosts` | SSH連携導入時に共通利用 | 既存のホスト別設定解決を流用。Windows資格情報をファイルへ書き出さない |
| `.rhai`マクロ | 初版はテキスト編集 | 既存マクロの実行互換は別機能。3270専用命令を対応済みにしない |
| `.yyd`（yydraw） | 初版は識別と情報参照。後続で専用プレビュー | 図形・配置・埋込素材を落として再保存しない |
| `.yy3d`（YY3Designer） | 初版は識別と情報参照。後続で投影プレビュー | レイヤー・6方向画像・厚み・削り情報を保持。初版は書込み不可 |
| `.yyer.yaml`・`.yyplan`（yydbmanager） | 初版は識別と構造／原文参照 | ERや計画をDBへ適用しない。専用編集は後続範囲 |
| `*.yymerge-session.json` | 原文参照、必要に応じCLI連携 | マージ状態の意味を変えて保存しない。専用編集は後続範囲 |

図形・3D等の情報参照は、形式を正しく解釈する共有リーダーを導入できたものから行う。単なるバイナリのテキスト表示を専用ビューと呼ばない。未対応バージョンは変更不可とし、形式・対応範囲を表示する。

将来の未知属性を既存ライブラリが保持できない場合、必要な保持機構を共通側へ追加するか、その保存を禁止する。画面上で見えない情報を削って保存する方式は採用しない。独自に仕様を写して似たファイルを作ることも避ける。

## 8. 実装方式と既存資産の再利用

### 8.1 構成案

Rustで実装し、OS非依存の文書・データ処理とLinux／端末依存の入出力を分ける。TUIフレームワークはRatatuiとCrosstermを第一候補とし、M0で入力・日本語・SSH経路・PTYとの同時動作を検証して採否を決める。

Ratatuiはセル／バッファとバックエンドを分けた描画を提供するが、文書モデルや巨大ファイル管理を代替するものではない。[公式の描画説明](https://www.ratatui.rs/concepts/rendering/)を参照し、既存YYコアの上にTUI表示を実装する。

```text
キー・マウス・貼り付け・リサイズ
             ↓
       コマンド／フォーカス管理
             ↓
        ワークスペース状態
        ├ 文書・ピースツリー・Undo
        ├ CSV／固定長／YYSモデル
        ├ Gitバックグラウンド処理
        ├ PTY管理 → yy-term画面モデル
        └ Markdown構文木
             ↓
   表示範囲・文字幅 → セルバッファ → 親端末

低速I/O・索引・検索・変換はワーカープールへ分離
進捗／結果はジョブID・文書世代を付けてUIへ戻す
```

### 8.2 流用候補と必要な作業

| 既存資産 | 流用する内容 | CUI側での作業 |
| --- | --- | --- |
| `yy-buffer`・`yy-core` | ピースツリー、文書、履歴、編集・検索の中核 | コマンド・セル座標・カーソルとの接続 |
| `yy-io`・`yy-jobs`・`yy-search` | I/O、保存、非同期処理、索引・検索 | Linuxの外部更新安全性と予算管理を検証 |
| `yy-layout`・`yy-syntax` | 長大行分割、表示範囲、構文色 | 端末のセル幅・書記素単位へ適合 |
| YYLibraryの`yy-encoding` | 日本語・EBCDIC・独自対応表 | 同じバージョンを固定し、一覧・試験を共用 |
| `yy-delimited`・`yy-sheet` | CSV解析、列・チャンク、YYS、レイアウトカタログ | 表・フィルター・セル編集のCUI |
| `yy-cobol`・`yy-numfmt`・`yy-formula` | COBOL型、数値、式・表示形式 | 項目検証と既存意味論の維持 |
| `yy-term` | VT解釈、画面、スクロールバック、キー符号化 | Linux PTY・親端末への描画 |
| `yy-git` | Gitコマンド操作 | Git画面、ジョブ、認証経路の接続 |
| `yy-config`・`yy-remote`・`yy-ssh` | YY形式の設定、SSH、SFTP／SCP、共通ポリシー | SSH機能導入時のCUIダイアログとLinux資格情報 |
| `yy-preview` | Markdown解析・変換の一部、関連資産 | 端末用レンダラーを新設。WebView2の代用にはしない |
| yymergeのコア／CLI | 巨大差分、3方向マージの候補 | 依存境界と画面連携を別途評価 |

`yy-win`、DirectWrite／Direct2D、ConPTY、WebView2の画面は直接移植しない。既存のLinux試験が通ることと、新しいCUIとして安全・快適に動くことは別に検証する。

### 8.3 リポジトリと共通ライブラリの管理

新アプリのソースとCIは本リポジトリに置く。開始時点の流用は、既存リポジトリ内クレートへの完全なGitコミット固定等で再現可能にする。単純なファイルコピーで別実装を増やさない。

継続的に両製品が利用するコアは、YYLibraryへの適切な抽出を第一候補にする。抽出は依存関係・ライセンス・テスト・形式互換を整理して行い、Windows版も同じ共通資材を参照する。UIを共通ライブラリに逆依存させない。

`yy-encoding`は既にYYLibraryが本体である。既存調査時の固定先は`57deca92c834227f705496fd7c5c4a226ec8dc97`。実装開始時には採用する各共有資材の固定SHAを決め、Cargo.lockと互換性マニフェストへ残す。

現行yyeditorの流用コードはGPL-3.0-or-laterを基準にライセンスを整理する。新アプリの配布条件は採用するソース・ライブラリの条件を確認して決定し、独自にMIT等へ変更した前提にしない。フォントは同梱しないため、フォント配布の工程は設けない。

## 9. 設定・CLI・ヘルプ

アプリ固有設定は`$XDG_CONFIG_HOME/yyterminal-editor/`、未指定なら`~/.config/yyterminal-editor/`を基本にする。YY共通の文字コード対応表・レイアウト・SSHプロファイルは明示的な共通パス設定で参照する。UI設定を既存Windowsアプリ用config.tomlへ混在させない。

CLI案は次のとおり。正式な引数名は実装前に確定する。

```sh
yyte .
yyte README.md
yyte --workspace project.yyworkspace
yyte --encoding IBM-930 --record-length 256 data.dat
yyte --layout layouts/order.yyl data.dat
yyte --csv orders.csv
yyte --check-terminal
yyte --memory-limit 1GiB --jobs 4 --temp-dir /scratch huge.log
```

設定はキーバインド、色、幅ポリシー、CSV既定値、表示予算、外部ツール、共有資材パスを含む。秘密情報は通常の設定・履歴へ保存しない。Windows資格情報マネージャーの保存値をLinuxへ自動コピーせず、Linux側の資格情報利用方針を別に定める。

F1のパレット内に「ヘルプ」を置き、オフラインの検索可能なヘルプを同梱する。利用者向け原稿はMarkdownで一元管理し、CUIヘルプと配布用文書を生成する。対応構文・形式・文字コード・端末制約・復旧手順・CSV／固定長の保存規則を記載する。

文書は利用者向け`docs/user`、開発者向け`docs/developer`、企画案`docs/proposal`、日付付き検証結果`docs/history`へ分ける。

## 11. 品質・性能・互換性の受入条件

### 11.1 操作・端末

- 初めて起動した人が、F1またはメニューからファイルを開く・保存・Git・端末・ヘルプへ到達できる。
- 80×24／120×36／200×60でレイアウトが破綻せず、拡大縮小で編集中の文字やセルを失わない。
- Linuxの主要端末、SSH経路、tmux／screen経由で、キーの代替操作を含む試験を行う。対象ソフトと版は試験記録へ残す。
- 全角・結合文字・曖昧幅・絵文字・非UTF-8ファイル名を含む選択・コピー・検索・リサイズを確認する。
- 強制中止を含む終了後、端末のecho・rawモード・カーソル・マウス追跡が復元される。

### 11.2 データと形式

- 既存Windows版→CUI→Windows版、および逆方向の往復試験を行う。
- 未編集テキスト・CSV・固定長はハッシュ一致を確認し、未編集の不正バイト・SO／SI・パック十進数を保持する。
- 固定長の単一／マルチレイアウト、DBCS境界、桁あふれ、未知レコード、COBOL数値型を共通のフィクスチャで試験する。
- `.yys`はセル、型、数式、書式、複数シート、レイアウト、フィルター等の意味を比較する。形式の内部配置が変わる保存ではファイル全体のバイト一致を要求しない。
- 未対応属性・将来バージョンは、保持できないなら保存を拒否する。
- 保存途中のディスク不足・中止・外部変更で原本を破壊しない。復旧データも原本を無断上書きしない。

### 11.3 巨大ファイルの測定目標

以下は測定条件を固定して検証する設計目標であり、現在の達成値ではない。

| 項目 | 測定方法・目標案 |
| --- | --- |
| データセット | 1／10／100 GiB、改行なし、100 MiB以上の長大行、巨大CSVフィールド、EBCDIC、固定長を用意 |
| 初回表示 | 10 GiBの安定したローカル通常ファイルで、全索引完了を待たず2秒以内を目標。スナップショット作成が必要な場合は時間と進捗を別に測る |
| 入力・スクロール | 120×36でアプリ側処理のp95を50 ms以下、遅いI/O中も中止操作へ応答することを目標 |
| メモリ | 初期予算1 GiBの設定で、大きさに比例した全展開をしない。RSS・索引・キャッシュ・Undo・一時領域を分けて記録 |
| 保存・全検索 | 処理量・時間・I/O・ワーカー数を記録し、中止可能。元データ保護と保存後の内容一致を必須にする |
| PTY大量出力 | 出力を制限した場合もUI入力が処理され、スクロールバックが予算を超えて無制限に増えない |

測定環境はCPU、RAM、ファイルシステム、ストレージ、端末ソフト、画面サイズ、warm／cold、SSH遅延、圧縮・tmuxの有無を記録する。疎ファイルだけで巨大ファイル対応を合格にしない。

### 11.4 CIと配布

本リポジトリ独立のLinux CIでfmt、全ワークスペース・全対象Clippy、単体／プロパティ試験、実PTY試験、実Git試験、データ互換試験を行う。構造体や共有型の変更では、利用側も含めた全対象をコンパイルする。

描画スナップショットだけでなく、実PTYからキー・貼り付け・リサイズ・子プロセス終了を与え、期待する状態を期限付きで確認する。固定sleepのみを完了条件にしない。必要な外部プログラムを明示的に導入し、必須試験の未導入スキップを成功扱いにしない。

Windows版との互換性は共有フィクスチャとバージョンごとの相互運用ジョブで検証する。既存YYリポジトリのWindows CIを新CUIの毎回必須条件にはせず、共有資材更新時の連携検証として接続する。

配布はLinux x86_64／aarch64のアーカイブを基本とし、musl静的版とglibc版の可否をM0で確認する。Windows／macOS版を初版の必須要件にはしない。ヘルプ、ライセンス、依存通知、必要なデータ資材を同梱し、**フォントは同梱しない**。

## 12. 初期に解決する論点

1. 端末が受信できるキーの範囲と、VS Code風操作の代替経路。
2. Linuxで外部更新される巨大ファイルの安全性と、スナップショットに必要な一時領域。
3. `.yys`等で、CUIにない表示機能の属性を欠落させず保存できるか。
4. 端末セル幅と、Unicode・ホスト文字コード・固定長バイト幅の対応。
5. 既存コアのGit依存で開始する範囲と、YYLibraryへ抽出する範囲。
6. 初版の基本Git差分と、yymerge CLIへ委ねる高度な比較の境界。

いずれもM0の検証結果として残し、未確定点を「既存資産があるから実装不要」とみなさない。
