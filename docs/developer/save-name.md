# 保存候補名の拡張子推定

`src/save_name.rs`が保存画面用の候補パスを返し、`App::ask(Prompt::Save)`が入力欄へ設定する。判定はyyeditor `cf298314ec9de2f0024c6d49280aa9241ad58f20`の`crates/yy-win/src/app/saveformat.rs`の保存仕様に対応する。Windows専用の保存画面に依存せず、既存の共有`yy-syntax::Registry`と`yy-delimited::split_line`を利用する。共有クレートのソースや文字コード表は複製せず、Git SHA固定も変更しない。

通常は既存の拡張子・Makefile/Dockerfile・ドットファイルを優先して維持する。アウトライン表示だけは`.json`へ候補を変更する。拡張子なし・新規文書では、表示モード、手動ハイライト、先頭64KiBの内容の順で決める。端末固有のワークブックは`.yys`、raw表示は`.bin`。元ファイルのディレクトリは維持する。候補は助言であり、確定時には拡張子の追加も形式変換もしない。

内容推定はSnapshotから最大64KiBだけ読み、UTF-8表示用の文字列として調べる。BOM・前後空白を除き、SVG、共有レジストリのshebang/モードライン、JSON（未完成も含む）、マークアップ、JSONL、Markdownのフェンス、明確な言語構文、見出し、区切り文字、設定形式、リスト、CSSの順に判定する。行単位の判定は128非空行まで。区切り文字は128物理行・32レコードまでで、引用フィールドの複数行を共有パーサーで扱い、列数が2以上で一致する2レコード以上を要求する。判定不能時は`.txt`。

上書き保存・外部変更検出・不正バイト保持は既存の保存経路を利用し、推定結果はDocumentへ書き戻さない。モデル試験は形式・優先順・既存名・64KiB境界を、App試験は表示モードと入力されたパスの尊重を検証する。Linux実PTY試験は候補名をEnterで確定する保存と、Ctrl+Uで変更する保存の実ファイル内容を確認する。
