# 開発・検証

## ビルド

`rust-toolchain.toml` の Rust 1.99.0 を利用する。LinuxではGitとシェルが実行できること。端末にはUTF-8と通常のANSIカーソル操作が必要。アイコンフォント、WebView、X11は必須としない。

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --release --locked
cargo run --locked -- --help
```

`.github/workflows/ci.yml` は独立したLinux/Windows CI。LinuxではPTYの実接続と実際のCUI操作を試験する。WindowsでLinux専用試験が0件になることをLinux検証の代わりにしない。CIが未実行の場合、ローカル試験の成功だけでGitHub CI成功と表現しない。

## 内部構成

- `src/main.rs`: 状態、キーマップ、コマンド、ワーカーとのメッセージ、CLI。
- `src/data.rs`: 共有CSVパーサーとCOBOLコーデックによる表モデル。ページ読込は最大128レコード・1MiB・4096列。CSVはレコード境界を保ち、固定長は原本バイトの項目範囲だけを書き換える。矩形貼り付けは全件検証後に1つのUndo単位で適用する。
- `src/editor.rs`: YYのDocumentをラップし、専用ディレクトリへストリームコピーして原本の可変mmapを避ける。読み込み前後のSHA-256を照合する。
- `src/shell.rs`: portable-ptyで生成したシェルの入出力をyy-termに接続。出力キューとスクロールバックは有界。子のANSIを外側端末へ直接出力しない。
- `src/git.rs`: 引数をシェル展開せずGitへ渡す。操作はワーカー上で実施。現在は出力全体をメモリへ取得するため大規模diffは未最適化。
- `src/ui.rs`: Ratatuiの画面描画、Markdownから端末テキストへの変換。待機中は変更があった場合だけ再描画する。
- `tests/cui.rs`: Linuxの実PTYで日本語貼り付け、保存、シェル通信、リサイズ、画面切り替え、終了を確認する。

保存は共有モデルのスナップショット・元文字コード・不正バイト復元規則を使用する。原本とのハッシュ照合後、共有IOによる置換保存を行う。新規保存は同一ディレクトリ上の一時ファイルから上書き禁止で確定する。保存中に続けて行った編集は、保存した版と現在版を区別して未保存のまま残す。タブ終了・アプリ終了は処理中に許可しない。

ハッシュ照合と置換の間の他プロセスによる変更を排他的にロックする仕組みはまだない。他プロセスと同じ原本を同時保存する用途は未対応。開く・保存する処理の進捗割合、キャンセル、クラッシュ時の編集復旧も今後の実装対象。

可視行は1行あたり最大16KiB、画面幅で分割し、巨大な単一行全体をStringにしない。Markdownは先頭128MiB、検索はカーソルの次から16MiBに制限する。プレビュー変換はワーカー上で実施する。全容量対応には専用索引が必要。

## 共有コード

`yy-core`、`yy-buffer`、`yy-io`、`yy-jobs`、`yy-config`、`yy-term`、`yy-delimited`、`yy-cobol`、`yy-sheet` は yyeditor の完全なGit SHAで固定。`yy-encoding` はその依存先であるYYLibraryの固定SHAを利用する。実装や文字コード表をこのリポジトリへ複製しない。依存の更新時にはCargo.lockと互換性試験を更新する。

Linux検証に使用したコンテナは `rust:1.99.0-bookworm`。実PTY試験にはホスト画面やX11は必要ない。非TTY環境で対話UIを直接起動せず、`cargo test` のPTY試験または `--help` を使用する。

## 表モードの注意点

固定長は別のraw文書として原本をコピーする。テキストへの変換を経由せず、保存もUTF-8 literal経路を使ってバイト列を直接出力する。通常のテキスト入力へ切り替えない。読み込んだcopybookのフィールド型を使い、書込みでoverflow/truncated/unencodable等のIssuesが発生すれば変更を適用しない。Decimalは指定スケールに変換して戻した値も照合し、小数桁の暗黙の切り捨ても拒否する。

CSVのセル変更は対象フィールドだけをquoteして置換する。他フィールドの引用符の有無、CRLF/LF、末尾改行の有無を変更しない。表示は1MiBを上限とし、末尾が未完のCSVレコードは編集対象にしない。ページの次位置から続きを読み、戻るために訪問済みページの先頭位置を保持する。ファイル全体の行番号索引・総件数や任意行への直接ジャンプは未実装。

ページ読込結果はDocumentのVersionと照合し、古い版の結果を反映しない。元文書をテキストモードで変更した場合は表のページを先頭から再構築する。表モード自身のフィールド変更では、変わらないページ先頭を保持して再読込する。ページ読込中の保存はタブ番号と保存先をキューに持ち、作業終了後に実行する。同じタブへの保存要求は最新のものへまとめる。

固定長のレコード長、文字コード、区切りは毎回明示する。LayoutのREDEFINESなどの扱いは共有COBOLパーサーに従う。マルチレイアウト、.yylの保存・推定・適用、.yys編集は以下の共有モデルで対応する。Windowsのモデル試験だけでなく、Linux実PTYでCSV・固定長のメニュー操作と保存結果のバイト列を検証する。


## ブック・固定長エクスポート・比較

`src/workbook.rs` は共有 yy-sheet の Document/Workbook/Sheet を使用する。編集は Document.edit で一括適用し、失敗時にロールバックする。数式・行列参照調整・オートフィル・ソート・フィルターは共有エンジンに委譲する。UIからのモデル変更はブックをワーカーへ所有権移動し、成功/失敗どちらでも返却する。

行高は共有形式にないため、通常の疎なシート `__yyte_view_v1` のA1に `YYTE_ROW_HEIGHTS_V1` を保存し、(元行+1, 対象シート番号) に高さを保存する。行挿入削除で対応する列のメタデータを移動する。列幅・書式は共有モデルの標準フィールド。外部YYアプリとの互換性を壊す独自バイナリ拡張は加えないが、外部アプリでは補助シートが見える可能性がある。

固定長の元レコードは読み取り専用列 `__YYTE_ORIGINAL_RECORD` に区切りを含めたhexで保持し、チャンク化して保存する。通常UI・CSV出力からは隠す。`src/fixed_export.rs` は元レコードへ元フィールド位置で値を重ね、元デコード値と同じ値のフィールドは書換えない。桁落ちを検証し、全件書込み・flush/sync後に上書き禁止で確定する。列削除された項目は元バイトを保つ。欠けたメタデータからの復元や、未確定マルチレイアウトの暗黙の書出しは行わない。

.yys保存APIはチャンクのStoreを保存先へrelocateする。このためまず専用一時フォルダーへ保存し、閉じた配布用一時ファイルへコピーしてから確定する。書込用Storeが利用者のファイルを保持して外部変更を妨げることを避ける。ブックを開く際も専用コピーを使う。

`src/layouts.rs` は共有 yy-sheet catalog の .yyl をそのまま読み書きし、共有推定APIから編集可能な提案を生成する。複数候補の選択は共有モデルの名前順・デコード可否規則に従うため、レコード識別子による業務上のレイアウト選択は人が確認する。

`src/diff.rs` は yy-merge-core::large をGit SHA固定で利用する。元文書のスナップショットと比較用コピーのスナップショットを保持し、ディスク索引から可視行だけ取得する。差分ジャンプも共有索引を用いる。表示文字列を4096バイトに制限しても比較は全文を対象とする。Git差分コマンドの出力取得は別経路で、こちらは依然として全体をメモリへ取得する。


## 共通Markdownレンダラーと単独コマンド

`src/lib.rs` が `preview` と `mermaid` を公開し、yyteと `src/bin/markdown_viewer.rs` の両方で利用する。Cargoのdefault-runは従来どおりyyte。CIは両コマンドをビルド・配布し、markdownViewerの非TTY実行も確認する。

Markdownはpulldown-cmarkのイベントをLine/Spanへ変換する。画像のデコードはimage、HTTPの明示的な取得はreqwest/rustlsで実施する。寸法・デコードメモリ・入力バイト数を制限し、画像の色を2ピクセル/セルのTruecolor半ブロックまたはASCII輝度へ変換する。Markdown由来の制御文字を無害化し、HTML・スクリプトを実行しない。画像の再取得はプレビュー再生成単位で行う。

Mermaidは制限付きの独自パーサーからノード・エッジへ変換する。DAGは入次数を使う階層配置、循環/横幅超過はノード一覧と関係カードで表示する。シーケンスは別のライフライン配置を使う。装飾や未対応構文の扱いは利用者文書へ明記し、未知の図は原文へ戻す。ブラウザーMermaidの完全な互換エンジンではない。

yyteのプレビューは文書版・タブ・表示幅・ネットワーク設定をキーにキャッシュし、再描画ごとにデコードしない。変換中も別操作を処理する。プレビュー専用メッセージは一般のbusyフラグを解除しない。単独ビューアーも再生成をワーカーで行う。リサイズ時に幅が変われば再生成する。ネットワーク試験は外部サイトに依存せず、期限付きのローカルHTTP接続を使用する。


## マウスのメニュー・エクスプローラー

描画時に実際のRectへMouseActionを登録する。上部の表示幅、Explorerの表示開始行、メニューのListState.offsetからヒット領域を構成し、端末サイズやスクロール位置を固定値としない。メニューはキーボード操作と同じcommandへ、ExplorerはEnterと同じ非同期のopen_selected_entryへ接続する。メニュー表示中は背景の項目へクリックを通さず、入力プロンプトも保護する。端末マウスのSGRイベントをLinux実PTYで入力し、メニュー、新規タブ、子フォルダー、ファイル、親フォルダーの画面反映を期限付きで確認する。


## 共通タブ、分割プレビュー、マウス編集

既存文書の非同期ジョブ・保存キューのタブ番号を保つため、タブのコンテナーに文書またはPTY Shellを保持する。シェルはタブごとに独立し、非表示のタブもpollする。select_tabでフォーカス・表示種別を更新し、処理中のタブ削除は引き続き禁止する。端末タブのDropはShellのkill/waitを通じて子を回収する。Ctrl+Tab/ Ctrl+Wは端末へ送る前にアプリ側で処理する。

テキストのマウス位置は描画済みの行バイト範囲とgrapheme単位の表示幅から求める。手動スクロール時はfollow_caretを外し、編集・クリック時に復帰する。文字・タブの表示幅と選択範囲を合わせる。入力ダイアログ、文書/端末タブ、タブの閉じる操作も描画時のRectへ登録する。モーダル表示中の背景操作は禁止する。

分割プレビューは同じタブの文書スナップショットを既存ワーカーで描画する。編集側とプレビュー側のRect・フォーカス・スクロールを分離する。ビュー幅をキーに再生成し、非表示時は生成しない。48セル未満のコンテンツは上下配置、24セル未満または6行未満は編集のみを表示する。画像処理中も編集・タブ操作を妨げない。

表のリサイズではドラッグ中の寸法を表示だけに適用し、Upイベントで一度だけモデルへ反映する。ワークブックの変更はDocument.edit経由でUndoできる。raw表は列/レコード番号ごとの表示寸法マップを持ち、ファイルのバイトを変更しない。単独ビューアーもEnableMouseCapture/DisableMouseCaptureを復元ガードで管理する。


## メニューとエクスプローラー

`src/commands.rs` の安定した英語コマンドIDを実行と試験で共用し、`MENUS` が用途別の配置、`label` が日本語表示を定義する。表示文字列でコマンドを判定しない。F1の全コマンド一覧、カテゴリーメニュー、ファイルの右クリックメニューは同じ実行処理を利用する。`Menu` と `Command` のマウス領域は描画時の端末セル幅から生成し、日本語のカテゴリー名も正しい位置で選択する。

ツリーは展開済みパス集合と可視パス一覧を持つ。展開対象だけをワーカーで読み込み、成功した結果を該当ディレクトリの直後に挿入する。折りたたみは子孫のパスと展開状態を除去する。展開操作では実行コンテキストの `root` を変更しない。一覧は1フォルダー10,000、ツリー全体20,000項目に制限する。折り返した各表示行に同じファイル選択アクションを割り当てる。CSV等の明示的なオープンでは、そのファイルの非同期オープン結果だけにモードを適用する。固定長は入力された定義から直接バイト列を開き、既存の未保存タブを経由しない。

メニュー言語とエクスプローラーモードは利用者設定の `ui.conf` に一時ファイルから置換保存する。テストでは `YYTE_CONFIG_DIR` を隔離し、利用者の設定を読み書きしない。表示言語を切り替えてもコマンドID、パス、データの文字コードは変更しない。


## Markdownの容量と表の描画

文書上限は128MiB、描画行は100万、画像参照は256、出力幅は4096セル。文書境界はUTF-8の文字境界に戻して省略を通知する。yyteは上限に数バイトを足したスナップショット範囲を読んで共通レンダラーで境界を処理し、単独ビューアーは超過した入力を拒否する。

`src/preview_table.rs` がMarkdownの表イベントを受け、内容・指定した配置・インラインスタイルを保持したセルからグリッドを組版する。列記号、行番号、見出し、交互の背景、罫線、セル内改行を描く。各列の自然幅は4～64セルで自動調整し、最低幅でも収まらない場合はグリッド幅を保って横に移動する。行数予算を表の出力とセルの折り返しにも適用する。

`src/preview_layout.rs` が書式と書記素の境界を維持した折り返し・切り出しを担当する。通常文はワーカーで表示行に分割する。グリッドは再折り返ししない。画面には `Rendered::viewport` で可視部分だけを渡し、全行のcloneやParagraphのu16スクロールに依存しない。スクロール位置はusize、最大表示幅はワーカーで一度算出する。単独ビューアーの再組版はArcで原稿を共有し、印字はBufWriterでまとめる。


## シンタックスハイライト

`yy-syntax` を他のYYクレートと同じ完全SHAで参照し、定義や解析実装を複製しない。`src/syntax.rs` が組み込みRegistryをOnceLockで共有し、TokenIdの名前を端末の色・装飾へ対応づける。プレビューはコードブロックごとに状態を分離し、エディタは各タブに非同期キャッシュを保持する。Markdown原稿のフェンスは長さ・種類と埋め込み言語の状態を保持する。

エディタ要求のキーは文書Version・パス・言語指定・可視バイト範囲。ワーカーは周辺256KiBと可視部分最大256KiBを読み、64KiB間隔の行頭チェックポイントを保存する。互換性のある前回結果のチェックポイントだけを再利用する。原本全体の走査はしない。遠い位置への初回移動は周辺のみから状態を近似し、論理行64KiBを超えた部分は共有解析器の上限に従って通常表示する。編集中の世代と一致しない結果は表示に利用しない。

トークンのバイト範囲を表示行へ交差させ、選択範囲の背景だけを重ねる。タブ展開・CRLF・日本語・不正バイトの代替表示を従来の位置対応と一致させ、UTF-8途中の解析上限で文字を欠落させない。ハイライトは文書への編集・保存処理を行わない。

CIの過去の失敗原因と対策は[CI失敗分析](../history/ci-failure-analysis.md)を参照してください。


## リリースのアーキテクチャ

配布ツールはPython 3.11以上を使い、CIはPython 3.13を明示する。CIはLinux／Windowsのx86_64とARM64の4環境で、fmt・Clippy・テスト・releaseビルドと `tools/release.py verify` を実行する。ARM64はそれぞれ `ubuntu-24.04-arm` と `windows-11-arm` 上でネイティブ実行する。Rustホストはmatrixの完全ターゲット名で固定し、x64エミュレーションでビルドした資材をARM版として扱わない。実行ファイルのPE/ELF機械種別、バージョン、ヘルプ、Markdownの余白・表・画像・構文色も確認する。各CIの資材名にはOSと `X64`／`ARM64` を含める。

GitHub上で対象SHAの4ジョブが成功した後、配布資材を取得して全アーキテクチャをまとめる。

```sh
gh run download RUN_ID --repo ykwyuta/yyterminal-editor --dir target/distribution/artifacts
python tools/release.py package --artifacts target/distribution/artifacts --output target/distribution/packages --version v0.7 --commit FULL_COMMIT_SHA --ci-run https://github.com/ykwyuta/yyterminal-editor/actions/runs/RUN_ID
```

WindowsはZIP、Linuxは実行権限付きtar.gz。ファイル名の `x86_64`／`arm64` がCPUを示す。4種類すべてを必須とし、実行形式の機械種別が一致しない場合や既存のステージがある場合は失敗させる。ヘルプ・デモ・README・ライセンスは指定コミットから取得する。BUILDINFO.jsonにソースSHA・CI・ターゲット・バイナリSHA-256を記録し、SHA256SUMS.txtを出力する。ARM資材をx86ホストで実行したとは表現せず、CIのネイティブ検証結果を使う。

ランナーの対応は[GitHub公式仕様](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)を参照。Markdownのブロック間余白は `Output` の遅延した区切りとして処理し、段落・見出し・リスト・表・コードの境界で1行だけ確保する。区切りも描画行数予算に含む。


見出しの装飾は `Output::heading` で組版する。H1/H2はプレビュー幅いっぱいの二重／一重の箱、H3/H4は太い／細い下線、H5/H6は別の接頭記号を付ける。書記素単位の折り返しと装飾行の追加に同じ行数予算を適用し、幅が6セル未満では箱を使わない。
リストは開始番号を持つスタックと項目ごとの接頭記号・初回フラグを分離する。`Output::push` は記号幅を差し引いて本文を折り返し、続きの行に同じ幅の空白を付ける。項目内の追加段落でも記号を繰り返さない。インライン装飾はスタイルのスタックで合成・復帰する。実端末の図表示試験は表示領域と共通レンダラーから接続情報の位置を算出し、固定ページ数を仮定しない。


## データベース機能

`yy-db-core` を他のYYクレートと同じ完全SHAで参照する。接続・SQL分割・実行・スプール・計画ファイル解析・計画ラベルとコスト・ERモデル・転送の実装をコピーしない。`database.rs` の専用ワーカーがセッションと結果セットを保持し、UIは128行のページと要約だけを受け取る。接続セッションは名前ごとに保持し、切断時に破棄する。UIのDropで中断し、チャンネルを閉じてワーカーをjoinする。

`db_app.rs` は接続ウィザード、オブジェクトツリー、SQLタブ、結果グリッド、プロパティ、ERとメニューを仲介する。`database_plan.rs` は元のdrawingの配置をセル座標へ変換し、元のlabels/details/flow_width/warningを使用する。画面内だけを描き、巨大なキャンバスを全セル展開しない。図の選択はデータ上のノードindexへ対応し、エッジのプロパティも区別する。ER文書のview情報は読み込み・再保存時に保持する。

Linuxは `apt-get install libssl-dev pkg-config cmake` が必要。`yy-db-core` は `default-features = false` で参照し、既定機能 `odbc`（`odbc-api`）を無効にする。このためWindowsの `odbc32`、Linuxの unixODBC へリンクしない。汎用ODBC接続文字列とDb2実測計画は使用できない。`database.rs` はODBC形式の接続先を保存・接続の両方で拒否し、`db_app.rs` はDb2の実測計画をSQL送信前に拒否する。`tools/release.py verify` と梱包処理は、ELFの `DT_NEEDED` とPEのインポート表・遅延インポート表を読み、`libodbc.*`／`odbc32.dll` へのリンクがあれば失敗する。同梱文書の文字列はリンクとして扱わない。DuckDB 1.4.1の同梱C++ビルドのためCIは2ジョブを上限とし、初回ビルドの時間枠とキャッシュを分ける。Windows x64はVS 2022を維持する。ARM64は各ネイティブCIで検証する。

Windowsのモデル／画面バッファ試験のほか、Linux実端末試験でSQLの結果・コピー・計画とサイズ変更を確認する。7種類の計画fixtureは `demo/database` に置く。直接接続の実サーバー試験とファイルだけの描画試験は区別する。

- [外部5DB実接続試験（yydbmanagerと同じCompose・シナリオ）](database-live-tests.md)

実DBの画面例を更新する場合は `python tools/render_plan_examples.py target/database-live/<成功した実行時刻>` を使います。本体の描画関数から利用者向けSVG・テキストを生成します。

- [描画性能の測定とキャッシュ検証](render-performance.md)

Windows ARM64の `windows-11-arm` はVS 2026へ移行しているため、同梱DuckDB 1.4.1のfmtと互換性のある併設v143（MSVC 14.44）をVsDevCmdで選択する。ARM64ホスト・ARM64ターゲット、PATH／INCLUDE／LIBとVCToolsVersionを維持し、CIが出力する版を確認する。コンポーネント不在は準備失敗とする。

### DBメニューとFileIndex

親メニューのView > Database ManagementからDB画面を開く。接続・SQL・検索結果・計画・ERの5メニューは画面内に配置し、ポップアップも画面内に収める。DB画面のF10は接続メニューを開き、左右キーはDBの5分類内で循環する。F1は全コマンド一覧を開く。

ターミナルエディタはFileIndexを利用しない。固定SHAの`yy-db-core`は`duckdb = 1.4.1`を`bundled`で直接依存しているため、FileIndexを無効にしてもDuckDBのC++ビルドは削減されない。DuckDBはDB接続機能に必要であり、現在の共有クレートにはこれを除外するfeatureがない。
