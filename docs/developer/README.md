# 開発・検証

## ビルド

`rust-toolchain.toml` の Rust 1.99.0 を利用する。LinuxではGitとシェルが実行できること。端末にはUTF-8と通常のANSIカーソル操作が必要。アイコンフォント、WebView、X11は必須としない。

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --release --locked
cargo run --locked -- --help
```

`.github/workflows/ci.yml` は独立したLinux/Windows CI。LinuxではPTYの実接続と実際のCUI操作を試験する。WindowsでLinux専用試験が0件になることをLinux検証の代わりにしない。CIが未実行の場合、ローカル試験の成功だけでGitHub CI成功と表現しない。

## 内部構成

- `src/main.rs`: 状態、キーマップ、コマンド、ワーカーとのメッセージ、CLI。
- `src/data.rs`: 共有CSVパーサーとCOBOLコーデックによる表モデル。ページ読込は最大128レコード・1MiB・4096列。CSVはレコード境界を保ち、固定長は原本バイトの項目範囲だけを書き換える。矩形貼り付けは全件検証後に1つのUndo単位で適用する。
- `src/editor.rs`: YYのDocumentをラップし、専用ディレクトリへストリームコピーして原本の可変mmapを避ける。読み込み前後のSHA-256を照合する。
- `src/shell.rs`: portable-ptyで生成したシェルの入出力をyy-termに接続。出力キューとスクロールバックは有界。子のANSIを外側端末へ直接出力しない。
- `src/git.rs`: 引数をシェル展開せずGitへ渡す。操作はワーカー上で実施。現在は出力全体をメモリへ取得するため大規模diffは未最適化。
- `src/ui.rs`: Ratatuiの画面描画、Markdownから端末テキストへの変換。待機中は変更があった場合だけ再描画する。
- `tests/cui.rs`: Linuxの実PTYで日本語貼り付け、保存、シェル通信、リサイズ、画面切り替え、終了を確認する。

保存は共有モデルのスナップショット・元文字コード・不正バイト復元規則を使用する。原本とのハッシュ照合後、共有IOによる置換保存を行う。新規保存は同一ディレクトリ上の一時ファイルから上書き禁止で確定する。保存中に続けて行った編集は、保存した版と現在版を区別して未保存のまま残す。タブ終了・アプリ終了は処理中に許可しない。

ハッシュ照合と置換の間の他プロセスによる変更を排他的にロックする仕組みはまだない。他プロセスと同じ原本を同時保存する用途は未対応。開く・保存する処理の進捗割合、キャンセル、クラッシュ時の編集復旧も今後の実装対象。

可視行は1行あたり最大16KiB、画面幅で分割し、巨大な単一行全体をStringにしない。Markdownは先頭1MiB、検索はカーソルの次から16MiBに制限する。検索・プレビューも全容量に対応する段階ではワーカー化と専用索引が必要。

## 共有コード

`yy-core`、`yy-buffer`、`yy-io`、`yy-jobs`、`yy-config`、`yy-term`、`yy-delimited`、`yy-cobol`、`yy-sheet` は yyeditor の完全なGit SHAで固定。`yy-encoding` はその依存先であるYYLibraryの固定SHAを利用する。実装や文字コード表をこのリポジトリへ複製しない。依存の更新時にはCargo.lockと互換性試験を更新する。

Linux検証に使用したコンテナは `rust:1.99.0-bookworm`。実PTY試験にはホスト画面やX11は必要ない。非TTY環境で対話UIを直接起動せず、`cargo test` のPTY試験または `--help` を使用する。

## 表モードの注意点

固定長は別のraw文書として原本をコピーする。テキストへの変換を経由せず、保存もUTF-8 literal経路を使ってバイト列を直接出力する。通常のテキスト入力へ切り替えない。読み込んだcopybookのフィールド型を使い、書込みでoverflow/truncated/unencodable等のIssuesが発生すれば変更を適用しない。Decimalは指定スケールに変換して戻した値も照合し、小数桁の暗黙の切り捨ても拒否する。

CSVのセル変更は対象フィールドだけをquoteして置換する。他フィールドの引用符の有無、CRLF/LF、末尾改行の有無を変更しない。表示は1MiBを上限とし、末尾が未完のCSVレコードは編集対象にしない。ページの次位置から続きを読み、戻るために訪問済みページの先頭位置を保持する。ファイル全体の行番号索引・総件数や任意行への直接ジャンプは未実装。

ページ読込結果はDocumentのVersionと照合し、古い版の結果を反映しない。元文書をテキストモードで変更した場合は表のページを先頭から再構築する。表モード自身のフィールド変更では、変わらないページ先頭を保持して再読込する。ページ読込中の保存はタブ番号と保存先をキューに持ち、作業終了後に実行する。同じタブへの保存要求は最新のものへまとめる。

固定長のレコード長、文字コード、区切りは毎回明示する。LayoutのREDEFINESなどの扱いは共有COBOLパーサーに従う。マルチレイアウト、.yylの保存・推定・適用、.yys編集は以下の共有モデルで対応する。Windowsのモデル試験だけでなく、Linux実PTYでCSV・固定長のメニュー操作と保存結果のバイト列を検証する。


## ブック・固定長エクスポート・比較

`src/workbook.rs` は共有 yy-sheet の Document/Workbook/Sheet を使用する。編集は Document.edit で一括適用し、失敗時にロールバックする。数式・行列参照調整・オートフィル・ソート・フィルターは共有エンジンに委譲する。UIからのモデル変更はブックをワーカーへ所有権移動し、成功/失敗どちらでも返却する。

行高は共有形式にないため、通常の疎なシート `__yyte_view_v1` のA1に `YYTE_ROW_HEIGHTS_V1` を保存し、(元行+1, 対象シート番号) に高さを保存する。行挿入削除で対応する列のメタデータを移動する。列幅・書式は共有モデルの標準フィールド。外部YYアプリとの互換性を壊す独自バイナリ拡張は加えないが、外部アプリでは補助シートが見える可能性がある。

固定長の元レコードは読み取り専用列 `__YYTE_ORIGINAL_RECORD` に区切りを含めたhexで保持し、チャンク化して保存する。通常UI・CSV出力からは隠す。`src/fixed_export.rs` は元レコードへ元フィールド位置で値を重ね、元デコード値と同じ値のフィールドは書換えない。桁落ちを検証し、全件書込み・flush/sync後に上書き禁止で確定する。列削除された項目は元バイトを保つ。欠けたメタデータからの復元や、未確定マルチレイアウトの暗黙の書出しは行わない。

.yys保存APIはチャンクのStoreを保存先へrelocateする。このためまず専用一時フォルダーへ保存し、閉じた配布用一時ファイルへコピーしてから確定する。書込用Storeが利用者のファイルを保持して外部変更を妨げることを避ける。ブックを開く際も専用コピーを使う。

`src/layouts.rs` は共有 yy-sheet catalog の .yyl をそのまま読み書きし、共有推定APIから編集可能な提案を生成する。複数候補の選択は共有モデルの名前順・デコード可否規則に従うため、レコード識別子による業務上のレイアウト選択は人が確認する。

`src/diff.rs` は yy-merge-core::large をGit SHA固定で利用する。元文書のスナップショットと比較用コピーのスナップショットを保持し、ディスク索引から可視行だけ取得する。差分ジャンプも共有索引を用いる。表示文字列を4096バイトに制限しても比較は全文を対象とする。Git差分コマンドの出力取得は別経路で、こちらは依然として全体をメモリへ取得する。
